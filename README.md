# REELCHECK — 나노 인플루언서 콘텐츠 자동 1차 검수 도구

REELCHECK는 인플루언서가 올린 광고 영상을 AI가 자동으로 훑어보고, 캠페인 가이드라인(브랜드명·제품명·필수 언급 사항·금칙어)을 지켰는지 1차로 걸러주는 내부 도구입니다.

마케터가 영상 수십~수백 개를 하나씩 재생하며 "브랜드명 제대로 말했나, 금칙어 안 썼나"를 눈으로 확인하는 일을 줄이는 게 목적입니다. AI가 1차로 걸러낸 결과를 보고, 애매한 건만 사람이 다시 확인하면 됩니다.

이 문서는 기획/운영 담당자가 "지금 이 도구가 정확히 뭘 하는지"를 이해하는 걸 목표로 합니다. 뒷부분에는 개발자를 위한 설치·실행 가이드도 있습니다.

---

## 1. 화면 구성

REELCHECK는 화면이 두 개로 나뉘어 있고, 상단 바에서 전환합니다. (현재는 로그인 없이 누구나 두 화면에 접근할 수 있습니다 — 8번 "알려진 제약사항" 참고)

### 1-1. 마케터 화면

**① 캠페인 생성 탭**
- 광고주명, 프로젝트명, 캠페인 기간(연/월), 담당자를 입력해 캠페인을 만듭니다.
- 캠페인은 서로 완전히 독립적입니다. A캠페인에 등록한 인플루언서 명단·가이드라인은 A캠페인에서만 쓰입니다.
- 만든 캠페인 목록이 표로 보이고, "이 캠페인으로 검수" 버튼으로 작업할 캠페인을 선택합니다.

**② 검수 대시보드 탭** (캠페인을 선택해야 보임)
- **가이드라인 입력** (기본은 접혀 있고, 클릭하면 펼쳐지는 아코디언 형태)
  - 정확한 브랜드 표기명, 정확한 제품 표기명
  - 필수로 언급되어야 하는 USP(제품 핵심 장점) 목록 — 여러 개 추가 가능
  - 금칙어/금기사항 목록 — 여러 개 추가 가능
  - **저장** 버튼을 눌러야 실제로 저장됩니다 (자동 저장 아님). 저장하면 서버(Supabase)에 반영되어, 새로고침하거나 다른 컴퓨터에서 열어도 유지됩니다.
- **실시간 통계 스코어보드**: 총 대상 인원, AI 자동 통과, 가이드 위반(반려), 검수 대기(+통과율)를 숫자로 보여줍니다.
- **명단 대량 등록**: 엑셀(xlsx/xls/csv) 파일로 인플루언서 명단(이름, 핸들)을 한 번에 등록합니다. "양식 엑셀 다운로드" 버튼으로 샘플 양식을 받을 수 있습니다.
  - ⚠️ 이 업로드는 **해당 캠페인의 기존 명단을 통째로 교체**합니다. 이미 검수가 끝난 인플루언서가 있는 상태에서 다시 업로드하면 그 결과도 함께 사라지니 주의가 필요합니다.
- **검수 현황 테이블**: 인플루언서별 이름/핸들, 제출 상태, AI 판정(통과/반려/-), "상세 피드백" 버튼을 보여줍니다. 반려 사유는 상세 피드백 팝업에서 확인합니다(4번 참고).

### 1-2. 인플루언서 업로드 화면

- 마케터가 등록해둔 명단이 그대로 표로 나타납니다.
- 인플루언서(또는 대신 업로드하는 에이전시 담당자)가 각자의 행에서 **영상 파일을 선택**하면 바로 서버로 전송되어 자동 검수가 시작됩니다.
- 제출 상태와 검수 상태(통과/반려)가 실시간으로 갱신됩니다. "반려"를 클릭하면 반려 사유 팝업이 뜹니다.
- 이 화면은 별도 로그인 없이 링크 하나로 누구나 접근 가능한 형태로 운영 중입니다 (에이전시가 여러 인플루언서 영상을 한꺼번에 올리는 방식을 고려한 설계).

## 2. 자동 검수는 실제로 무엇을 하는가

영상 하나가 업로드되면, 두 단계로 나뉘어 진행됩니다. 굳이 나눈 이유는 8-3번에 설명되어 있습니다.

### 2단계 파이프라인 요약

```
영상 업로드
   │
   ├─▶ [1단계 · 음성] 오디오 추출 → Whisper로 전사(텍스트 변환)
   │                    → 가이드라인과 대조해 1차 판정
   │                    → 화면에 "검수완료(음성)"으로 즉시 표시 (보통 10~30초)
   │
   └─▶ [2단계 · 자막, 화면 뒤에서 계속 진행] 영상을 480p로 저용량 변환
                        → 장면이 바뀌는 지점마다 화면 캡처(키프레임 추출)
                        → Tesseract OCR로 화면 속 글자 1차 인식
                        → 의심스러운 프레임만 GPT-4o Vision으로 정밀 재확인
                        → 자막 텍스트만으로 별도 판정
                        → 음성+자막을 합쳐 최종 종합 판정
                        → 화면이 자동으로 "검수완료"로 갱신됨 (보통 수십 초~수 분, 영상 길이·서버 상황에 따라 다름)
```

마케터/인플루언서는 아무것도 새로고침하지 않아도, 화면이 자동으로 최신 상태로 바뀝니다(5초 간격으로 서버에 확인하는 방식).

### 왜 "음성"과 "자막"을 따로 보는가

인플루언서가 말은 안 했지만 화면 자막으로만 브랜드명을 적어둔 경우, 반대로 자막엔 없지만 말로만 언급한 경우가 실제로 있습니다. 음성만 보거나 자막만 보면 이런 케이스를 놓치기 때문에 둘 다 확인하고, 최종 판정에서 종합적으로 반영합니다.

### 왜 화면 자막 인식에 두 가지 AI(Tesseract + GPT-4o Vision)를 같이 쓰는가

- **Tesseract**: 무료이고 빠르지만, 정확도가 GPT-4o Vision보다 떨어집니다. 모든 프레임(최대 60장)을 이걸로 먼저 훑습니다.
- **GPT-4o Vision**: 정확하지만 이미지 1장당 비용과 시간이 듭니다. 그래서 Tesseract가 "금칙어와 비슷한 글자를 읽었거나, 글자를 잘 못 읽은 것 같은" 프레임만 골라서 여기로 넘깁니다.
- 이렇게 하면 영상 1건당 GPT-4o Vision 호출을 몇 건 수준으로 줄이면서도, 오탈자로 위장한 금칙어("최 고" 처럼 띄어쓰기로 필터를 피하는 경우 등)까지 잡아낼 수 있습니다.

## 3. 검수 결과 화면 — 종합 / 음성 / 자막 탭 + 세부 발견 내역

"반려" 표시를 클릭하면 뜨는 팝업에서 다음을 확인할 수 있습니다.

- **탭 3개**: `종합` (최종 통과/반려를 결정하는 기준, 기본으로 보이는 탭) · `🎤 음성` (음성 전사만 봤을 때의 판정) · `🖼 자막` (화면 자막만 봤을 때의 판정)
- 각 탭에서: 브랜드 언급 여부(✅/❌), 제품명 언급 여부, 충족된 USP, 누락된 USP, 위반한 금칙어, AI가 남긴 한글 피드백 문장
- **세부 발견 내역 표**: 몇 초 지점에서, 어떤 문구가, 어떤 이유로(브랜드/제품/USP/금칙어/오타의심) 걸렸는지 한 줄씩 나열합니다. "종합" 탭에서는 그게 음성에서 나온 건지 자막에서 나온 건지도 같이 표시됩니다.

> 참고: 영상 원본 파일은 검수가 끝나면 서버에서 바로 삭제됩니다. 그래서 세부 발견 내역의 "시간"은 참고용 텍스트 정보이며, 클릭해서 그 장면으로 이동하는 기능은 없습니다.

> 참고: 음성 탭과 자막 탭 판정은 서로 별도로 AI에게 물어본 결과라, 아주 가끔 둘의 뉘앙스가 살짝 다르게 나올 수 있습니다(예: 자막 탭은 "언급됨"인데 종합 탭은 좀 더 엄격하게 판단하는 경우). 실제 통과/반려를 최종 결정하는 건 항상 "종합" 탭입니다.

## 4. 캠페인 데이터는 어떻게 관리되는가

캠페인, 인플루언서 명단, 검수 결과는 모두 **Supabase**(클라우드 데이터베이스)에 저장됩니다. 브라우저를 닫거나 다른 컴퓨터로 접속해도 그대로 유지됩니다.

| 구분 | 저장되는 내용 |
|---|---|
| 캠페인 | 광고주명, 프로젝트명, 기간, 담당자, 브랜드/제품 표기명, USP 목록, 금칙어 목록 |
| 인플루언서 | 이름, 핸들, 제출 상태, 통과/반려, 반려 사유 텍스트, 음성 전사 원문, 검수 결과 상세(JSON: 종합/음성/자막 판정 + 세부 발견 내역) |

## 5. 알려진 제약사항 / 한계

솔직하게 짚어야 할 부분들입니다.

- **대용량 영상(체감상 300MB 안팎 이상) 업로드가 "Failed to fetch"로 실패할 수 있습니다.** 업로드 자체(파일 전송)가 서버 인프라(Render/Cloudflare)의 응답 대기 한도(~100초) 안에 끝나지 않아서 생기는 문제입니다. 처리 시간 문제가 아니라 "전송 시간" 문제라, 지금 구조로는 근본 해결이 어렵고 업로드 방식 자체를 바꿔야 합니다(예: 서버를 거치지 않고 클라우드 스토리지에 직접 업로드).
- **로그인 기능이 아직 없습니다.** 마케터 화면/인플루언서 업로드 화면 모두 URL만 알면 누구나 접근 가능합니다. 구글 로그인 기반의 화면 분리 작업을 시도했으나, 사내망 프록시 환경 문제로 완전히 붙이지 못해 별도 브랜치에 보류된 상태입니다.
- **OpenAI 요청량이 몰리면(429 요청 한도 초과) 자막 검수가 실패할 수 있습니다.** 짧은 대기 후 자동 재시도하도록 만들어뒀지만, 그래도 실패하면 음성 판정만으로 최종 확정되고, 화면에는 "자막 검수 실패"라고 명시됩니다.
- **음성 인식(Whisper)이 실제 발화를 다르게 알아들을 수 있습니다.** 특히 신조어·특이한 발음의 제품명은 엉뚱한 단어로 잘못 전사될 수 있습니다. 브랜드/제품명을 힌트로 미리 주지 않는 이유는 아래 6-1에 설명되어 있습니다 (힌트를 주면 오히려 실제 오기입을 놓치게 됩니다).

## 6. 왜 이렇게 만들었는가 (설계 의도 Q&A)

**Q. Whisper에 브랜드명을 힌트로 주면 인식률이 더 좋아질 텐데, 왜 안 주나요?**
Whisper의 `prompt` 옵션은 고유명사 인식률을 올려주지만, 인플루언서가 실제로 "무드렙"이라고 잘못 말해도 힌트를 보고 "무드랩"으로 스스로 고쳐 적어버립니다. 검수에서 정작 잡아야 하는 게 이런 오기입인데, 힌트를 주면 그게 사라져버려서 의도적으로 비워뒀습니다.

**Q. 화면 자막 인식은 왜 crv(claude-real-video)로 프레임을 뽑나요? 그냥 1초에 한 장씩 뽑으면 안 되나요?**
릴스 영상은 컷 전환이 빠르고 정지 화면이 길게 이어지는 경우가 흔합니다. 일정 간격으로만 뽑으면 빠른 컷은 놓치고, 같은 장면에서는 중복된 프레임만 여러 장 얻게 됩니다. crv는 "장면이 실제로 바뀌는 지점"마다 뽑고 중복을 걸러내서, 같은 예산(프레임 수)으로 더 많은 실제 정보를 확보합니다.

**Q. 영상을 480p로 줄여서 검수하면 화질이 나빠서 자막을 놓치지 않나요?**
서버 사양(CPU)에 대비해 원본 해상도 그대로 처리하면 시간이 너무 오래 걸려서 저해상도 프록시 파일로 줄여서 처리합니다. 다만 세로형(릴스/쇼츠) 영상에서 무작정 줄이면 자막이 놓인 가로 폭이 과도하게 깎여 오히려 못 읽는 문제가 있었어서, 가로·세로 중 "짧은 변" 기준으로 최소 720px는 유지하도록 맞춰뒀습니다. 오디오는 화질과 무관해서 원본 그대로 사용합니다.

**Q. 왜 검수 완료까지 두 단계로 나뉘나요? 그냥 다 끝난 다음에 한 번에 보여주면 안 되나요?**
음성 검수는 빠르지만(수십 초), 화면 자막 검수(장면 추출 + OCR + AI 비전 검증)까지 다 마치려면 영상 길이나 서버 상황에 따라 훨씬 오래 걸릴 수 있습니다. 서버 인프라의 응답 대기 한도(~100초) 안에 다 끝내지 못하면 "Failed to fetch"로 아예 실패해버립니다. 그래서 빠른 음성 결과를 먼저 보여주고, 화면 자막은 백그라운드에서 계속 진행해 끝나면 화면을 자동 갱신하는 방식으로 바꿨습니다.

## 7. 기술 스택 요약

| 영역 | 사용 기술 | 비고 |
|---|---|---|
| 음성 → 텍스트 | OpenAI Whisper API (`whisper-1`) | 구간별 타임스탬프 지원이 필요해서 이 모델을 기본값으로 씀 |
| 화면 장면 추출 | claude-real-video (crv, Python) | 장면 전환 감지 + 중복 프레임 제거 |
| 화면 글자 1차 인식 | Tesseract.js | 무료·고속, 모든 프레임에 적용 |
| 화면 글자 정밀 검증 | OpenAI GPT-4o(-mini) Vision | 의심 프레임만 선별 적용 |
| 가이드라인 준수 판정 | OpenAI GPT-4o(-mini) (텍스트) | 음성 전용 / 자막 전용 / 종합, 총 3회 호출 |
| 데이터 저장 | Supabase (Postgres) | 캠페인/인플루언서/검수결과 |
| 백엔드 | Node.js + Express | `server.js` 단일 파일 |
| 프론트엔드 | React (Create React App) | `frontend/` |
| 배포 | 프론트: Vercel / 백엔드: Render | |

## 8. (개발자용) 설치 · 실행 가이드

### 8-1. 사전 설치

**ffmpeg / ffprobe** — crv 실행과 오디오 추출에 둘 다 필요합니다. pip로는 설치되지 않습니다.

| OS | 명령 |
|---|---|
| macOS | `brew install ffmpeg` |
| Ubuntu/Debian | `sudo apt install ffmpeg` |
| Windows | `winget install Gyan.FFmpeg` |

확인: `ffmpeg -version`

**claude-real-video**
```bash
pip install claude-real-video
crv --help   # 설치 확인
```
`[whisper]` 옵션은 설치할 필요 없습니다 — 전사는 OpenAI API로 처리합니다.

**Node.js** 20 이상 (`node -v`)

### 8-2. 환경변수 (`.env`, 저장소 루트)

`.env` 파일은 절대 커밋하지 마세요 (`.gitignore`에 이미 등록되어 있습니다).

```
# 필수
OPENAI_API_KEY=여기에_발급받은_키
SUPABASE_URL=여기에_Supabase_프로젝트_URL
SUPABASE_SERVICE_KEY=여기에_Supabase_서비스_롤_키

# 선택 (기본값 있음)
PORT=8787
STT_MODEL=whisper-1
STT_LANG=ko
REVIEW_MODEL=gpt-4o-mini
OCR_MODEL=gpt-4o-mini
CRV_BIN=crv
MAX_CONCURRENT_COMPRESSIONS=2
ALLOW_ORIGIN=http://localhost:3000

# 사내망 등 프록시를 거쳐야 외부 인터넷에 나갈 수 있는 환경에서만 설정
HTTPS_PROXY=
HTTP_PROXY=
```

- `OPENAI_API_KEY`는 [platform.openai.com](https://platform.openai.com)에서 발급합니다. **Restricted** 권한으로 만들고, **Limits → Usage limits**에서 월 한도를 걸어두는 걸 권장합니다.
- `SUPABASE_URL` / `SUPABASE_SERVICE_KEY`가 없으면 캠페인/인플루언서 관련 기능(`/api/campaigns*`, `/api/influencers/*`)은 503 에러를 반환합니다. 음성·자막 원리만 테스트하려면 없어도 `/api/transcribe`, `/api/frames`, `/api/inspect`는 동작합니다.

### 8-3. 실행

```bash
# 백엔드 (저장소 루트에서)
npm install
npm start

# 프론트엔드 (별도 터미널, frontend/ 폴더에서)
cd frontend
npm install
npm start
```

```bash
curl -s http://localhost:8787/api/health
# { "ffmpeg": true, "ffprobe": true, "crv": true, "openaiKey": true, "supabase": true, "sttModel": "whisper-1" }
```

### 8-4. API 엔드포인트

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/health` | 의존성(ffmpeg/crv/OpenAI키/Supabase) 설치·연결 상태 |
| GET | `/api/campaigns` | 캠페인 목록 |
| POST | `/api/campaigns` | 캠페인 생성 |
| PUT | `/api/campaigns/:id` | 캠페인 정보/가이드라인 수정 |
| GET | `/api/campaigns/:id/influencers` | 해당 캠페인의 인플루언서 명단 조회 |
| POST | `/api/campaigns/:id/influencers/bulk` | 명단 대량 등록 (기존 명단 전체 교체) |
| GET | `/api/influencers/:id` | 인플루언서 1건 조회 (검수 상태 폴링용) |
| PATCH | `/api/influencers/:id` | 인플루언서 정보 일부 수정 |
| POST | `/api/transcribe` | **영상 업로드 → 검수 시작.** 음성 판정을 즉시 반환하고, 화면 자막 검수는 백그라운드로 이어짐 |
| POST | `/api/frames` | 영상 → 키프레임 추출만 (디버그/파라미터 튜닝용) |
| POST | `/api/inspect` | 전사 + 프레임 추출을 한 번에 (프론트엔드는 쓰지 않는, 진단용 엔드포인트) |

`/api/transcribe` 응답 예시:
```json
{
  "duration": 58.2,
  "text": "전체 음성 전사 텍스트...",
  "segments": [{ "start": 0, "end": 8, "text": "..." }],
  "ocrPending": true,
  "review": {
    "result": "반려",
    "brandMentioned": false,
    "productMentioned": true,
    "matchedUsps": ["..."],
    "missingUsps": ["..."],
    "violatedBans": [],
    "feedback": "...",
    "occurrences": [{ "timestamp": 12.3, "source": "음성", "quote": "...", "type": "brand", "note": "..." }],
    "audio": { "...동일 구조..." },
    "caption": null
  }
}
```
`ocrPending: true`인 동안 프론트엔드는 `GET /api/influencers/:id`를 5초 간격으로 확인해, `status`가 `"검수완료"`로 바뀌면 `review.caption`이 채워진 최종 결과로 화면을 갱신합니다. 자막 검수가 실패한 경우 `review.caption`은 `{ "failed": true, "reason": "..." }` 형태로 채워집니다.

### 8-5. 배포 시 참고

- `ALLOW_ORIGIN`을 실제 프론트엔드 도메인으로 좁혀야 합니다 (`*`는 로컬 개발용).
- 배포 환경(컨테이너/Render)에 ffmpeg과 crv가 함께 설치되어 있어야 합니다.
- Render 플랜(CPU/메모리)이 낮으면 화면 자막 검수(crv 키프레임 추출)가 느려집니다. `review._timingsMs` 필드에 단계별 소요 시간이 기록되니, 실제 처리 속도를 보고 플랜을 조정하면 됩니다.
