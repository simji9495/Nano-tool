# InCensor(인센서) — 인플루언서 콘텐츠 1차 검수 솔루션

InCensor는 인플루언서가 올린 광고 영상을 AI가 자동으로 훑어보고, 캠페인 가이드라인(브랜드명·제품명·필수 포함 사항·경쟁 브랜드·금지 사항)을 지켰는지 1차로 걸러주는 내부 도구입니다.

마케터가 영상 수십~수백 개를 하나씩 재생하며 "브랜드명 제대로 말했나, 경쟁 브랜드나 금지어를 쓰지 않았나"를 눈으로 확인하는 일을 줄이는 게 목적입니다. AI가 1차로 걸러낸 결과를 보고, 애매하거나 반려된 건만 마케터가 최종 확인·판정하면 됩니다.

이 문서는 기획/운영 담당자가 "지금 이 도구가 정확히 뭘 하는지"를 이해하는 걸 목표로 합니다. 뒷부분에는 개발자를 위한 설치·실행 가이드도 있습니다.

## 1. 화면 구성

접속하면 순서대로 랜딩 페이지 → 홈 화면(역할 선택) → 실제 작업 화면으로 이어집니다. (현재는 로그인 없이 링크만 알면 누구나 접근 가능합니다 — 5번 "알려진 제약사항" 참고)

- **랜딩 페이지**: 제품 소개 마케팅 페이지. "Get Started"를 누르면 홈 화면으로 이동합니다.
- **홈 화면**: "제일기획"(마케터) / "MCN·에이전시"(인플루언서 업로드) 중 역할을 선택합니다. 이후에도 화면 상단 바의 토글로 두 역할을 오갈 수 있습니다.

### 1-1. 마케터 화면 ("제일기획")

**① 캠페인 선택 탭**
- 광고주명, 프로젝트명, 캠페인 기간(연/월), 담당자를 입력해 캠페인을 만듭니다.
- 캠페인은 서로 완전히 독립적입니다. A캠페인에 등록한 인플루언서 명단·가이드라인은 A캠페인에서만 쓰입니다.
- 만든 캠페인 목록이 표로 보이고, 선택된 캠페인의 버튼만 검정으로 강조됩니다. 버튼을 눌러 작업할 캠페인을 선택합니다.

**② 콘텐츠 검수 현황 탭** (캠페인을 선택해야 보임)
- **가이드라인 규칙 입력 폼** (기본은 접혀 있고, 클릭하면 펼쳐지는 아코디언 형태)
  - 정확한 브랜드 표기명, 정확한 제품 표기명
  - **필수 포함 사항** — 오디오 또는 자막에 반드시 포함되어야 하는 제품 USP 등. 여러 개 추가 가능.
  - **경쟁 브랜드명** — 기입한 문자 그대로(띄어쓰기만 무시) 정확히 매치해 잡아내는 전용 목록. "🏷️ 경쟁 브랜드 언급" 버튼으로 빠르게 추가하거나, 콤마로 구분해 한 번에 여러 개 입력할 수 있습니다.
  - **금지 사항** — 경쟁 브랜드가 아닌, 그 외 개념적인 금지 사항(예: "자극감 언급"). 문맥을 고려해 검수합니다 — "화한 느낌"은 찾아서 반려시키지만 "화한 느낌 없어서 좋아요"처럼 부정된 표현은 통과시킵니다.
  - **저장** 버튼을 눌러야 실제로 저장됩니다 (자동 저장 아님). 저장하면 서버(Supabase)에 반영되어, 새로고침하거나 다른 컴퓨터에서 열어도 유지됩니다.
- **실시간 통계 스코어보드**: 총 대상 인원, AI 자동 통과, 가이드 위반(반려), 검수 대기(+통과율)를 숫자로 보여줍니다.
- **명단 대량 등록**: 엑셀(xlsx/xls/csv) 파일로 인플루언서 명단(계정 핸들만)을 한 번에 등록합니다. "양식 엑셀 다운로드" 버튼으로 샘플 양식을 받을 수 있습니다. **이름은 수집하지 않습니다** — 계정 핸들만으로 식별합니다.
  - ⚠️ 이 업로드는 **해당 캠페인의 기존 명단을 통째로 교체**합니다. 이미 검수가 끝난 인플루언서가 있는 상태에서 다시 업로드하면 그 결과도 함께 사라지니 주의가 필요합니다.
- **검수 현황 테이블**: No. / 핸들 / 제출 상태 / AI 판정 / 마케터 판정 / 업로드 가능여부. AI 판정을 클릭하면 판정 상세 팝업이, 마케터 판정을 클릭하면 판정 작성 팝업이 뜹니다(3·4번 참고).

### 1-2. MCN·에이전시 업로드 화면

- 캠페인 선택 탭에서 마케터가 만들어둔 캠페인 중 하나를 골라 선택만 합니다 (이 화면에서는 캠페인을 새로 만들 수 없습니다).
- 콘텐츠 검수 현황 탭에 마케터가 등록해둔 명단이 그대로 표로 나타납니다: No. / 핸들 / 제출 상태 / AI 판정 / 마케터 판정 / 업로드 가능여부 / 영상 파일 업로드.
- 인플루언서(또는 대신 업로드하는 에이전시 담당자)가 각자의 행에서 **영상 파일을 선택**하면 바로 업로드·검수가 시작됩니다. 업로드 중에는 진행률(%)이 실시간으로 표시됩니다.
- AI 판정은 확인할 수 있지만, 마케터 판정을 직접 내릴 수는 없습니다(읽기 전용).
- 이 화면은 별도 로그인 없이 링크 하나로 누구나 접근 가능한 형태로 운영 중입니다 (에이전시가 여러 인플루언서 영상을 한꺼번에 올리는 방식을 고려한 설계).

## 2. 자동 검수는 실제로 무엇을 하는가

영상 하나가 업로드되면, 두 단계로 나뉘어 진행됩니다. 굳이 나눈 이유는 8-4번에 설명되어 있습니다.

```
영상 업로드
   │
   ├─▶ [1단계 · 음성] 오디오 추출 → Whisper로 전사(텍스트 변환)
   │                    → 가이드라인과 대조해 1차 판정
   │                    → 화면에 "검수완료(음성)"으로 즉시 표시 (보통 10~30초)
   │
   └─▶ [2단계 · 자막, 화면 뒤에서 계속 진행] 영상을 480~720p로 저용량 변환
                        → 장면이 바뀌는 지점마다 화면 캡처(키프레임 추출)
                        → Tesseract OCR로 화면 속 글자 1차 인식
                        → 의심스러운 프레임만 GPT-4o Vision으로 정밀 재확인
                        → 자막 텍스트만으로 별도 판정
                        → 음성+자막을 합쳐 최종 종합 판정
                        → 화면이 자동으로 "검수완료"로 갱신됨 (보통 수십 초~수 분, 영상 길이·서버 상황에 따라 다름)
```

마케터/인플루언서는 아무것도 새로고침하지 않아도, 화면이 자동으로 최신 상태로 바뀝니다(5초 간격으로 서버에 확인하는 방식).

### 판정 방식: 정확 매치(결정론적) + 문맥 판단(AI) 병행

브랜드명·제품명·경쟁 브랜드는 "정확히 뭐라고 썼는지"가 중요하고, 필수 포함 사항·금지 사항은 "문맥상 의미가 통하는지"가 중요합니다. 그래서 판정 방식을 나눴습니다.

- **브랜드명 / 제품명 / 경쟁 브랜드명 — 정확 매치 로직**: AI에게 판단을 맡기지 않고, 등록된 표기 그대로(띄어쓰기만 무시) 텍스트에서 직접 찾습니다. 정확히 일치하는 항목이 없어도 편집거리상 가까운 "근접 매치"가 있으면 통과에 포함하되, "표기 확인 필요" 배지를 남겨 마케터가 확인하게 합니다. 이렇게 나눈 이유는 OCR·음성 인식이 실제로는 정확히 표기했는데 잘못 읽었을 가능성과, 실제로 오탈자를 낸 경우를 구분해야 하기 때문입니다 — AI가 착각한 케이스로 자동 반려시키지 않으면서도, 확인이 필요하다는 신호는 남깁니다. 반대로 경쟁 브랜드는 보수적으로 판단합니다: 확실한 정확 매치만 위반으로 집계하고, 근접 매치는 위반으로 단정하지 않습니다.
- **필수 포함 사항 / 금지 사항 — LLM 문맥 판단**: GPT-4o(-mini)에게 표현이 달라도 같은 의미면 인정하도록 맡깁니다(예: "쿨링감"이 USP면 "청량한 느낌"도 충족). 금지 사항은 부정어를 반드시 반영합니다 — "화한 느낌"은 위반이지만 "화한 느낌 없이"는 위반이 아닙니다.

### 왜 화면 자막 인식에 두 가지 AI(Tesseract + GPT-4o Vision)를 같이 쓰는가

- **Tesseract**: 무료이고 빠르지만, 정확도가 GPT-4o Vision보다 떨어집니다. 모든 프레임(최대 60장)을 이걸로 먼저 훑습니다.
- **GPT-4o Vision**: 정확하지만 이미지 1장당 비용과 시간이 듭니다. 그래서 Tesseract가 "경쟁 브랜드·금지 항목과 비슷한 글자를 읽었거나, 글자를 잘 못 읽은 것 같은" 프레임만 골라서 여기로 넘기고, 위험도(확실한 위반 후보인지, 그냥 저신뢰인지)에 따라 이미지 해상도를 차등 배분해 OpenAI 요청 한도(TPM)를 아낍니다.
- 이렇게 하면 영상 1건당 GPT-4o Vision 호출을 몇 건 수준으로 줄이면서도, 오탈자로 위장한 금지어까지 잡아낼 수 있습니다.

## 3. 마케터 최종 판정 — AI 판정과는 별개입니다

AI 판정(통과/반려)은 어디까지나 1차 스크리닝입니다. **실제로 영상을 업로드해도 되는지는 마케터가 직접 판정하기 전까지 항상 "업로드 가능여부: X"입니다** — AI가 통과로 판정했더라도 마케터가 확인해서 "통과"를 누르기 전에는 자동으로 O가 되지 않습니다.

- 검수 현황 테이블의 "마케터 판정" 칸을 클릭하면 판정 팝업이 뜨고, 여기서 **통과** 또는 **코멘트 저장 및 반려** 버튼으로 직접 판정합니다. 반려 시에는 코멘트(반려 사유)를 반드시 입력해야 하며, 이 코멘트는 인플루언서/에이전시 화면에도 그대로 노출됩니다.
- "업로드 가능여부"(O/X)는 이 마케터 판정 결과만 따릅니다. AI 판정 결과와는 독립적입니다.
- 마케터 판정 버튼은 마케터 화면에서만 조작 가능하고, MCN·에이전시 화면에서는 결과를 읽기만 할 수 있습니다.

## 4. 검수 결과 화면 — 판정 상세 팝업

AI 판정(또는 마케터 판정 작성) 칸을 클릭하면 뜨는 팝업에서 다음을 확인할 수 있습니다.

- **탭 3개**: `종합` (최종 통과/반려를 결정하는 기준, 기본으로 보이는 탭) · `🎤 음성` (음성 전사만 봤을 때의 판정) · `🖼 자막` (화면 자막만 봤을 때의 판정)
- **상태 카드 4개**: 브랜드 언급 / 제품명 언급 / 필수 포함사항 / 금지사항 위반 — 확인됨(초록) · 표기 확인 필요·부분 충족(주황) · 언급되지 않음·위반(빨강)으로 한눈에 표시됩니다.
- **한 줄 요약**: 누락된 필수 포함 사항, 위반한 금지 사항, 표기 확인이 필요한 건수를 문장으로 요약합니다.
- **세부 발견 내역 표**: 몇 초 지점에서, 어떤 문구가, 어떤 이유로(브랜드/제품/USP/금지어/오타의심) 걸렸는지 한 줄씩 나열합니다. "종합" 탭에서는 그게 음성에서 나온 건지 자막에서 나온 건지도 같이 표시됩니다. "표기 확인 필요" 항목은 배경색으로 강조됩니다.

> 참고: 영상 원본 파일은 검수가 끝나면 서버에서 바로 삭제됩니다. 그래서 세부 발견 내역의 "시간"은 참고용 텍스트 정보이며, 클릭해서 그 장면으로 이동하는 기능은 없습니다.

> 참고: 음성 탭과 자막 탭 판정은 서로 별도로 AI에게 물어본 결과라, 아주 가끔 둘의 뉘앙스가 살짝 다르게 나올 수 있습니다. 실제 통과/반려를 최종 결정하는 건 항상 "종합" 탭이며, 그마저도 어디까지나 참고용 1차 판정이고 최종 업로드 가능 여부는 3번의 마케터 판정을 따릅니다.

## 5. 대용량 영상은 어떻게 업로드되는가

영상은 브라우저에서 우리 서버(Render)를 거치지 않고 **Cloudflare R2**(S3 호환 오브젝트 스토리지)에 직접 업로드됩니다.

```
브라우저 → (1) 서버에 업로드 URL 요청 (즉시 응답)
브라우저 → (2) 그 URL로 R2에 영상 직접 업로드 (진행률 % 표시)
브라우저 → (3) 서버에 "업로드 끝났다"고 알림 (즉시 응답, 실제 검수는 백그라운드)
서버     → (4) R2에서 영상을 내려받아 2번의 검수 파이프라인 실행 → 완료되면 R2에서 즉시 삭제
```

이렇게 나눈 이유는 서버 인프라(Render)의 요청 처리 시간 한도(~300초) 때문입니다. 영상 전송 자체가 이 한도 안에 못 끝나면 예전에는 "Failed to fetch"로 업로드가 실패했는데, 전송을 서버가 아니라 스토리지로 직접 보내는 구조로 바꿔서 이 한도의 영향을 받지 않게 했습니다. 브라우저가 업로드만 끝내고 3번 알림을 못 보내는 경우(창을 닫는 등)를 대비해, R2에 2시간 넘게 남아있는 파일은 30분 주기로 자동 정리됩니다.

## 6. 캠페인 데이터는 어떻게 관리되는가

캠페인, 인플루언서 명단, 검수 결과는 모두 **Supabase**(클라우드 Postgres 데이터베이스)에 저장됩니다. 브라우저를 닫거나 다른 컴퓨터로 접속해도 그대로 유지됩니다.

| 구분 | 저장되는 내용 |
|---|---|
| 캠페인 | 광고주명, 프로젝트명, 기간, 담당자, 브랜드/제품 표기명, 필수 포함 사항 목록, 경쟁 브랜드명 목록, 금지 사항 목록 |
| 인플루언서 | 계정 핸들(이름은 수집하지 않음), 제출 상태, AI 판정, 마케터 판정, 반려/코멘트 사유 텍스트, 음성 전사 원문, 검수 결과 상세(JSON: 종합/음성/자막 판정 + 세부 발견 내역) |

## 7. 알려진 제약사항 / 한계

솔직하게 짚어야 할 부분들입니다.

- **로그인 기능이 아직 없습니다.** 마케터 화면/인플루언서 업로드 화면 모두 URL만 알면 누구나 접근 가능합니다. 인증은 의도적으로 아직 붙이지 않은 상태입니다.
- **OpenAI 요청량이 몰리면(429 요청 한도 초과) 자막 검수가 실패할 수 있습니다.** 짧은 대기 후 자동 재시도하도록 만들어뒀고, 위험도에 따라 이미지 해상도를 차등 배분해 한도 소모를 줄여뒀지만, 그래도 실패하면 음성 판정만으로 최종 확정되고 화면에는 "자막 검수 실패"라고 명시됩니다.
- **음성 인식(Whisper)이 실제 발화를 다르게 알아들을 수 있습니다.** 특히 신조어·특이한 발음의 제품명은 엉뚱한 단어로 잘못 전사될 수 있습니다. 브랜드/제품명을 힌트로 미리 주지 않는 이유는 아래 8-1에 설명되어 있습니다 (힌트를 주면 오히려 실제 오기입을 놓치게 됩니다).

## 8. 왜 이렇게 만들었는가 (설계 의도 Q&A)

**Q. Whisper에 브랜드명을 힌트로 주면 인식률이 더 좋아질 텐데, 왜 안 주나요?**
Whisper의 `prompt` 옵션은 고유명사 인식률을 올려주지만, 인플루언서가 실제로 "무드렙"이라고 잘못 말해도 힌트를 보고 "무드랩"으로 스스로 고쳐 적어버립니다. 검수에서 정작 잡아야 하는 게 이런 오기입인데, 힌트를 주면 그게 사라져버려서 의도적으로 비워뒀습니다.

**Q. 화면 자막 인식은 왜 crv(claude-real-video)로 프레임을 뽑나요? 그냥 1초에 한 장씩 뽑으면 안 되나요?**
릴스 영상은 컷 전환이 빠르고 정지 화면이 길게 이어지는 경우가 흔합니다. 일정 간격으로만 뽑으면 빠른 컷은 놓치고, 같은 장면에서는 중복된 프레임만 여러 장 얻게 됩니다. crv는 "장면이 실제로 바뀌는 지점"마다 뽑고 중복을 걸러내서, 같은 예산(프레임 수)으로 더 많은 실제 정보를 확보합니다.

**Q. 영상을 480~720p로 줄여서 검수하면 화질이 나빠서 자막을 놓치지 않나요?**
서버 사양(CPU)에 대비해 원본 해상도 그대로 처리하면 시간이 너무 오래 걸려서 저해상도 프록시 파일로 줄여서 처리합니다. 다만 세로형(릴스/쇼츠) 영상에서 무작정 줄이면 자막이 놓인 가로 폭이 과도하게 깎여 오히려 못 읽는 문제가 있었어서, 가로·세로 중 "짧은 변" 기준으로 최소 720px는 유지하도록 맞춰뒀습니다. 오디오는 화질과 무관해서 원본 그대로 사용합니다.

**Q. 왜 검수 완료까지 두 단계로 나뉘나요? 그냥 다 끝난 다음에 한 번에 보여주면 안 되나요?**
음성 검수는 빠르지만(수십 초), 화면 자막 검수(장면 추출 + OCR + AI 비전 검증)까지 다 마치려면 영상 길이나 서버 상황에 따라 훨씬 오래 걸릴 수 있습니다. 서버 인프라의 응답 대기 한도(~300초) 안에 다 끝내지 못하면 요청이 실패해버립니다. 그래서 빠른 음성 결과를 먼저 보여주고, 화면 자막은 백그라운드에서 계속 진행해 끝나면 화면을 자동 갱신하는 방식으로 바꿨습니다. 영상 업로드 자체도 같은 이유로 서버를 거치지 않고 스토리지에 직접 올리도록 바꿨습니다(5번 참고).

**Q. 브랜드명·제품명·경쟁 브랜드는 왜 AI가 아니라 직접 텍스트 매칭으로 판정하나요?**
AI에게 통째로 맡기면 두 방향으로 틀립니다 — 실제 오탈자를 "그 정도면 맞다"고 봐주거나(과관대), 존재하지 않는 경쟁 브랜드를 지어내서 반려시키거나(과민반응) 합니다. 등록된 표기와 직접 대조하는 결정론적 로직으로 바꾸고, 애매한 근접 매치만 "확인 필요" 배지로 마케터에게 넘기는 쪽이 실제 케이스에서 더 정확했습니다.

|---|---|

| Ubuntu/Debian | `sudo apt install ffmpeg` |
| Windows | `winget install Gyan.FFmpeg` |

확인: `ffmpeg -version`

**claude-real-video**
```bash
pip install claude-real-video
crv --help   # 설치 확인
```
`[whisper]` 옵션은 설치할 필요 없습니다 — 전사는 OpenAI API로 처리합니다.

**Node.js** 20 이상 (`node -v`)

### 10-2. 환경변수 (`.env`, 저장소 루트)

`.env` 파일은 절대 커밋하지 마세요 (`.gitignore`에 이미 등록되어 있습니다).

```
# 필수
OPENAI_API_KEY=여기에_발급받은_키
SUPABASE_URL=여기에_Supabase_프로젝트_URL
SUPABASE_SERVICE_KEY=여기에_Supabase_서비스_롤_키

# 대용량 영상 직접 업로드용 (Cloudflare R2) — 없으면 /api/uploads/presign,
# /api/transcribe/from-storage가 503을 반환하고, 프론트는 이 기능을 못 씁니다
R2_ACCOUNT_ID=여기에_Cloudflare_계정_ID
R2_ACCESS_KEY_ID=여기에_R2_액세스_키
R2_SECRET_ACCESS_KEY=여기에_R2_시크릿_키
R2_BUCKET_NAME=reelcheck-uploads

# 선택 (기본값 있음)
PORT=8787
STT_MODEL=whisper-1
STT_LANG=ko
REVIEW_MODEL=gpt-4o-mini
OCR_MODEL=gpt-4o-mini
CRV_BIN=crv
MAX_CONCURRENT_COMPRESSIONS=2
ALLOW_ORIGIN=http://localhost:3000

# 사내망 등 프록시를 거쳐야 외부 인터넷에 나갈 수 있는 환경에서만 설정
HTTPS_PROXY=
HTTP_PROXY=
```

- `OPENAI_API_KEY`는 [platform.openai.com](https://platform.openai.com)에서 발급합니다. **Restricted** 권한으로 만들고, **Limits → Usage limits**에서 월 한도를 걸어두는 걸 권장합니다.
- `SUPABASE_URL` / `SUPABASE_SERVICE_KEY`가 없으면 캠페인/인플루언서 관련 기능(`/api/campaigns*`, `/api/influencers/*`)은 503 에러를 반환합니다. 음성·자막 원리만 테스트하려면 없어도 `/api/transcribe`, `/api/frames`, `/api/inspect`는 동작합니다.
- R2 관련 값은 Cloudflare 대시보드 → R2 → "Manage R2 API Tokens"에서 발급합니다. `ALLOW_ORIGIN`으로 지정한 프론트엔드 도메인이 R2 버킷 CORS 허용 목록에도 자동으로 반영됩니다(서버 기동 시 멱등하게 설정).

### 10-4. API 엔드포인트

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/health` | 의존성(ffmpeg/crv/OpenAI키/Supabase) 설치·연결 상태 |
| GET | `/api/campaigns` | 캠페인 목록 |
| POST | `/api/campaigns` | 캠페인 생성 |
| PUT | `/api/campaigns/:id` | 캠페인 정보/가이드라인 수정 |
| GET | `/api/campaigns/:id/influencers` | 해당 캠페인의 인플루언서 명단 조회 |
| POST | `/api/campaigns/:id/influencers/bulk` | 명단 대량 등록 (기존 명단 전체 교체) |
| GET | `/api/influencers/:id` | 인플루언서 1건 조회 (검수 상태 폴링용) |
| PATCH | `/api/influencers/:id` | 인플루언서 정보 일부 수정 (마케터 판정·반려 사유 등) |
| POST | `/api/transcribe` | 영상 업로드(멀티파트) → 검수 시작. 소용량/로컬 테스트용 |
| POST | `/api/uploads/presign` | 대용량 영상용: R2에 직접 업로드할 수 있는 서명된 URL 발급 (5번 참고) |
| POST | `/api/transcribe/from-storage` | R2에 업로드된 영상의 경로를 받아 검수 시작 (백그라운드 진행, 즉시 응답) |
| POST | `/api/frames` | 영상 → 키프레임 추출만 (디버그/파라미터 튜닝용) |
| POST | `/api/inspect` | 전사 + 프레임 추출을 한 번에 (프론트엔드는 쓰지 않는, 진단용 엔드포인트) |

`/api/transcribe`, `/api/transcribe/from-storage` 완료 시 인플루언서 레코드에 반영되는 검수 결과 구조:
```json
{
  "duration": 58.2,
  "text": "전체 음성 전사 텍스트...",
  "segments": [{ "start": 0, "end": 8, "text": "..." }],
  "ocrPending": true,
  "review": {
    "result": "반려",
    "brandMentioned": false,
    "productMentioned": true,
    "matchedUsps": ["..."],
    "missingUsps": ["..."],
    "violatedBans": [],
    "feedback": "...",
    "occurrences": [{ "timestamp": 12.3, "source": "음성", "quote": "...", "type": "brand", "needsReview": false, "note": "..." }],
    "audio": { "...동일 구조..." },
    "caption": null
  }
}
```
`ocrPending: true`인 동안 프론트엔드는 `GET /api/influencers/:id`를 5초 간격으로 확인해, `status`가 `"검수완료"`로 바뀌면 `review.caption`이 채워진 최종 결과로 화면을 갱신합니다. 자막 검수가 실패한 경우 `review.caption`은 `{ "failed": true, "reason": "..." }` 형태로 채워집니다.

### 10-5. 배포 시 참고

- `ALLOW_ORIGIN`을 실제 프론트엔드 도메인으로 좁혀야 합니다 (`*`는 로컬 개발용).
- 배포 환경(컨테이너/Render)에 ffmpeg과 crv가 함께 설치되어 있어야 합니다.
- Render 플랜(CPU/메모리)이 낮으면 화면 자막 검수(crv 키프레임 추출)가 느려집니다. `review._timingsMs` 필드에 단계별 소요 시간이 기록되니, 실제 처리 속도를 보고 플랜을 조정하면 됩니다.
- R2 고아 파일 자동 정리(2시간 경과 후 삭제, 30분 주기 확인)는 서버가 계속 켜져 있는 것을 전제로 합니다. Render를 idle-sleep 플랜으로 바꾸면 별도 Cron Job으로 옮겨야 할 수 있습니다.
